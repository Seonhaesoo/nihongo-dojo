# 콘텐츠 제작 규격 (CONTENT SPEC)

「일본어 도장」은 **한국어가 모국어인 완전 초보자**가 12주(84일) 동안 JLPT N5 전 범위를 끝내는 집중 학습 앱이다.
모든 학습 콘텐츠는 `data/` 아래의 JSON 파일이며, 이 문서가 그 규격이다.

- 기준표: `tools/syllabus.json` — 날짜별 어휘 목록, 문법 레슨 목록(scope 포함), 한자 순서, 독해·청해 id
- 검증기: `node tools/validate.mjs <파일...>` — **오류 0건이 될 때까지 반드시 돌릴 것**
- 한자 → day 배정표 출력: `node tools/kanji-plan.mjs`

## 0. 공통 원칙

1. **정확성이 최우선.** 학습자는 여기 적힌 것을 그대로 외운다. 읽기(특히 今日=きょう, 明日=あした, 一人=ひとり, 二十歳=はたち 같은 숙자훈, 연탁, 촉음), 활용, 조사를 한 글자씩 재확인할 것. 확신이 없는 예문은 더 단순한 문장으로 바꾼다.
2. **설명은 한국어, 자연스러운 존댓말(~합니다/~해요 중 "~합니다/~입니다"체).** 일본어 문법 용어는 한국 학습서 관용을 따른다(ます형, て형, ない형, 사전형, た형, 보통형, 1·2·3그룹 동사, い형용사, な형용사).
3. **한국어와의 비교를 적극 활용.** 어순·조사·한자어가 거의 대응한다는 점이 한국인 학습자의 최대 무기다. 같은 점은 "한국어와 같다"고 짧게, **다른 점은 반드시 짚는다** (예: 友達に会う = 친구**를** 만나다, バスに乗る = 버스**를** 타다, 日本語がわかる = 일본어**를** 알다).
4. **난이도 통제.** 예문은 그 day까지 배운 문법(`syllabus.grammar`의 day 순서)과 N5 수준 어휘로 만든다. Day 12~31의 예문은 です/ます체만 쓴다(사전형·て형은 Day 32~33에 처음 나온다). 문장은 짧게(일본어 기준 25자 이내 권장).
5. 일본어 문장부호는 전각(。、？！「」), 의문문은 `〜ですか。`처럼 마침표로 끝낸다(반말 의문문은 `？`).
6. 파일은 UTF-8(BOM 없음), 들여쓰기 2칸, 최상위는 배열.

## 1. 후리가나 마크업

한자에는 **예외 없이** 읽기를 단다. 형식은 `{한자|읽기}`.

```
{私|わたし}は{学生|がくせい}です。
{毎朝|まいあさ}6{時|じ}に{起|お}きます。        ← 오쿠리가나(きます)는 중괄호 밖
{3時|さんじ}に{会|あ}いましょう。               ← 숫자+조수사는 숫자까지 묶어 읽기를 단다
{友達|ともだち}と{一緒|いっしょ}に{映画|えいが}を{見|み}ました。
```

- 중괄호 앞부분에는 한자(와 숫자·々)만, 뒷부분에는 가나만 쓴다. `{食べ|たべ}る` ✗ → `{食|た}べる` ✓
- 숙자훈은 통째로: `{今日|きょう}`, `{大人|おとな}`, `{一人|ひとり}`, `{上手|じょうず}`
- 마크업이 필요한 필드(아래 표에서 ★)뿐 아니라 **한국어 설명문 안에 일본어 한자를 쓸 때도** 똑같이 단다. 예: `"explain": "{約束|やくそく}는 한국어 '약속'과 발음까지 비슷합니다."`
- 설명문에서는 `**굵게**` 강조와 줄바꿈 `\n`만 쓸 수 있다. 그 밖의 마크다운/HTML 금지.
- 마크업을 쓰지 않는 필드: 어휘의 `jp`/`kana`/`cog`, 한자의 `kanji`/`hun`/`on`/`kun`/`words[].jp`.

## 2. 어휘 — `data/vocab/*.json`

```json
{
  "id": "v-d17-01",
  "day": 17,
  "jp": "起きる",
  "kana": "おきる",
  "ko": "일어나다",
  "pos": "동사2",
  "note": "ます형은 {起|お}きます. '깨다'와 '기상하다' 둘 다 됩니다.",
  "ex": { "jp": "{毎朝|まいあさ}{6時|ろくじ}に{起|お}きます。", "ko": "매일 아침 6시에 일어납니다." }
}
```

| 필드 | 설명 |
|---|---|
| `id` | `v-d{day 2자리}-{순번 2자리}`. 순번은 syllabus에 적힌 순서대로 01부터 |
| `day` | syllabus의 day |
| `jp` | **syllabus 문자열과 글자 하나까지 동일**하게. 단 `家(いえ)`의 괄호 부분은 읽기 힌트이므로 뺀다 → `"家"` |
| `kana` | 읽기. 히라가나(외래어는 가타카나). 동사·형용사는 사전형 |
| `ko` | 한국어 뜻. 간결하게(20자 이내), 뜻이 여럿이면 `, `로 구분. 핵심 뜻을 맨 앞에 |
| `pos` | `명사` `대명사` `동사1` `동사2` `동사3` `い형용사` `な형용사` `부사` `접속사` `의문사` `조사` `감탄사` `연체사` `표현` `접미사` `수사` 중 하나 |
| `cog` | (선택) 한국어에도 **같은 한자어**가 있을 때만. 형식 `"학생(學生)"` — 한국 한자음 + 정자체 한자. 뜻이 달라도 같은 한자어면 적는다(예: 勉強 → 쓰지 않음(한국어에 없는 말), 約束 → `"약속(約束)"`, 大丈夫 → `"대장부(大丈夫)"`) |
| `note` ★ | (선택) 한국인 학습자에게 필요한 주의점. 60자 이내. 조사 차이, 동음이의어, 자·타동사 짝, 1그룹 예외 동사 등 |
| `ex` ★ | 예문 1개 `{ "jp", "ko" }`. 표제어가 실제로 들어가야 한다. `pos`가 `표현`이면 생략 가능 |

- 동사 `pos`: 1그룹=`동사1`, 2그룹=`동사2`, する·来る·〜する=`동사3`. **る로 끝나는 1그룹 예외**(帰る, 入る, 走る, 知る, 切る, 要る 등)를 틀리지 말 것.
- な형용사의 `jp`에는 な를 붙이지 않는다(`静か`).
- Day 12~31의 예문에서 동사는 ます형으로 활용해 쓴다.

## 3. 한자 — `data/kanji.json`

```json
{
  "id": "kj-日",
  "day": 19,
  "kanji": "日",
  "hun": "날 일",
  "ko": "날, 해, 일(日)",
  "on": ["ニチ", "ジツ"],
  "kun": ["ひ", "か"],
  "strokes": 4,
  "words": [
    { "jp": "日曜日", "kana": "にちようび", "ko": "일요일" },
    { "jp": "毎日", "kana": "まいにち", "ko": "매일" },
    { "jp": "三日", "kana": "みっか", "ko": "3일, 사흘" }
  ],
  "tip": "한국 한자음 '일'이 음독 ニチ에 대응합니다. ㄹ받침 한자는 일본어에서 チ/ツ로 끝나는 경우가 많습니다(일→イチ, 팔→ハチ, 월→ゲツ)."
}
```

- 대상은 `syllabus.kanjiOrder`의 104자 전부, `day`는 `node tools/kanji-plan.mjs` 출력대로.
- `hun`: 한국식 훈음(천자문식). `on`: N5~N4에서 실제로 쓰이는 음독만, 가타카나. `kun`: 히라가나, 오쿠리가나는 `.`으로 구분(`た.べる`). 드문 읽기는 넣지 않는다.
- `words`: 3~4개. N5 수준의 실용 단어, 가능하면 음독 단어와 훈독 단어를 섞는다.
- `tip` ★ (선택이지만 적극 권장): **한국 한자음 ↔ 일본 음독 대응 규칙**, 모양이 비슷한 한자와의 구별, 읽기 주의점 등 한국인에게 실제로 도움이 되는 한두 문장.

## 4. 문법 레슨 — `data/grammar/*.json`

```json
{
  "id": "g01",
  "day": 12,
  "title": "〜は〜です",
  "titleKo": "명사문: ~은/는 ~입니다",
  "summary": "명사로 끝나는 가장 기본적인 문장입니다. 어순이 한국어와 똑같습니다.",
  "points": [
    {
      "pattern": "N1 は N2 です",
      "meaning": "N1은/는 N2입니다",
      "explain": "조사 **は**는 주제를 나타내며 한국어 '은/는'에 해당합니다. 글자는 は(ha)지만 조사로 쓰일 때는 **[wa]**로 읽습니다. です는 '입니다'입니다.",
      "examples": [
        { "jp": "{私|わたし}は{学生|がくせい}です。", "ko": "저는 학생입니다." },
        { "jp": "キムさんは{韓国人|かんこくじん}です。", "ko": "김 씨는 한국인입니다." }
      ]
    }
  ],
  "table": { "caption": "명사문 4형태", "head": ["", "긍정", "부정"], "rows": [["현재", "〜です", "〜じゃありません"]] },
  "compare": "어순과 조사의 쓰임이 한국어와 1:1로 대응합니다. 한국어로 생각한 순서 그대로 단어만 바꾸면 됩니다.",
  "pitfalls": ["조사 は를 [ha]로 읽는 실수. 조사일 때는 항상 [wa]입니다."],
  "quiz": [
    { "type": "choice", "q": "{私|わたし}（　）{学生|がくせい}です。", "ko": "저는 학생입니다.", "choices": ["は", "を", "の", "か"], "answer": 0, "explain": "주제를 나타내는 조사는 は입니다." },
    { "type": "order", "tokens": ["キムさんは", "{韓国人|かんこくじん}", "じゃありません"], "ko": "김 씨는 한국인이 아닙니다." }
  ]
}
```

| 필드 | 설명 |
|---|---|
| `id`, `day`, `titleKo` | syllabus 그대로 |
| `title` ★ | syllabus의 title에 후리가나 마크업만 추가 (예: `{助数詞|じょすうし}`) |
| `summary` ★ | 1~2문장 요약 |
| `points` | 2~6개. syllabus의 `scope`를 **빠짐없이** 다룬다. `pattern` ★(접속 형태 공식), `meaning`(한국어 대응), `explain` ★(2~5문장), `examples`(2~5개, `jp` ★ + `ko`) |
| `table` | (선택) 활용표·읽기표. 객체 하나 또는 객체 배열. `caption`, `head`, `rows`(모든 행의 열 개수 = head 길이). 셀도 ★ |
| `compare` ★ | (선택, 적극 권장) 한국어와 비교 |
| `pitfalls` ★ | (선택, 적극 권장) 한국인이 자주 틀리는 점 1~4개 |
| `quiz` | **8문항**: `choice` 5개 + `order` 3개 |

퀴즈 규칙
- `choice`: `q` ★에 빈칸은 전각 `（　）`. `choices` 4개(★ 가능), `answer`는 0부터 시작하는 인덱스 — **정답 위치를 골고루 섞을 것**. `explain` ★은 왜 정답인지 + 헷갈리는 오답이 왜 틀렸는지. 정답이 둘이 될 수 있는 보기 구성 금지.
- `order`: `tokens`는 **정답 순서대로** 나열(앱이 섞는다). 3~7개. 어순이 하나로 정해지도록 **조사는 앞 단어에 붙여서** 한 토큰으로 만든다(`{学校|がっこう}へ`). 그래도 다른 순서가 자연스러우면 `alts`에 인덱스 순열을 추가(`"alts": [[1,0,2,3]]`). 같은 토큰 중복 금지. 마침표는 넣지 않는다.
- 퀴즈는 그 레슨에서 배운 내용으로 풀 수 있어야 한다.

## 5. 독해 — `data/reading/reading.json`

```json
{
  "id": "r01", "day": 73,
  "title": "{私|わたし}の{一日|いちにち}", "titleKo": "나의 하루",
  "text": ["문단1 ★", "문단2 ★"],
  "ko": ["문단1 해석", "문단2 해석"],
  "vocab": [ { "jp": "毎朝", "kana": "まいあさ", "ko": "매일 아침" } ],
  "questions": [
    { "q": "この{人|ひと}は{何時|なんじ}に{起|お}きますか。", "qKo": "이 사람은 몇 시에 일어납니까?", "choices": ["{6時|ろくじ}", "{7時|しちじ}", "{8時|はちじ}", "{9時|くじ}"], "answer": 1, "explain": "…" }
  ]
}
```

- N5 실전 독해 수준(150~300자), 뒤로 갈수록 조금씩 길고 어렵게. 유형을 다양하게: 일기, 메모/안내문, 편지·메일, 설명문.
- `questions` 3개씩. `vocab`에는 본문 핵심 어휘 5~8개.

## 6. 청해 — `data/reading/listening.json`

```json
{
  "id": "l01", "day": 75,
  "title": "카페에서 주문하기",
  "situation": "점원과 손님의 대화입니다. 손님이 무엇을 주문했는지 잘 들어 보세요.",
  "lines": [ { "sp": "A", "jp": "いらっしゃいませ。ご{注文|ちゅうもん}は？", "ko": "어서 오세요. 주문은요?" } ],
  "questions": [ { "qKo": "손님은 무엇을 주문했습니까?", "choices": ["커피", "홍차", "주스", "물"], "answer": 0, "explain": "…" } ]
}
```

- 앱이 TTS로 대사를 읽어 준다(스크립트는 문제를 푼 뒤에 공개). `sp`: `A`/`B`(화자), `N`(내레이션).
- 대화 6~10줄, `questions` 2개. JLPT N5 청해처럼 시간·장소·물건·이유를 묻는다. 보기는 한국어.

## 7. 제출 전 체크리스트

- [ ] `node tools/validate.mjs <내 파일>` → 오류 0건, 경고는 하나씩 확인
- [ ] 읽기·활용·조사 재검토 (특히 숙자훈, 연탁, 조수사 음변화, 1그룹 예외 동사)
- [ ] 한국어 번역이 직역투가 아니라 자연스러운가
- [ ] 난이도가 해당 day에 맞는가
